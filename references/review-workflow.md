# 文字稿、预览与成品

## Markdown 文字审阅

生成实际可编辑的 `.md` 文件，用标题标示各页主题、分隔线区分页面。只写实际要显示的文字：

- 页面标题、正文与完整要点。
- 表格实际显示的行列、数值、单位，以及图中实际显示的节点、步骤和连接标签。
- 必须向观众展示的来源、条件与限定。

不附图示或排版建议、讲稿、材料介绍、视觉规范、审阅说明、版本状态或整套页序清单；不加“拟上屏文字”“主标题”等制作栏目，不重复标题。版本放文件名，修改方法在对话中说明。用户另要辅助说明时再提供。

实际目录页属于上屏内容，应在其对应页面写出“目录”标题与真实章节条目；这里排除的是制作说明性质的页序清单，不是演示中的目录页。

用途、总页数、章节映射、稳定的页面标识、设计规划和完整来源追溯留在工作区。材料不足的疑问在对话中提出，不编成上屏定论。交付后等待当前文字稿确认；若用户修改了文件，读取实际修订内容，不用旧稿推测新稿。

## HTML 视觉审阅

根据确认后的文字稿制作完整逐页预览，不仅展示封面或少量样页。预览呈现拟交付 PPT 的实际配色、字重、字号比例、图文构图、关系图、表格、章节导航和结束页，不能用目录网页、文字线框或旧幻灯片截图代替。

- 优先交付单个离线 HTML；若有资源目录，应一并提供。资源不能依赖制作者的私有绝对路径或未交付文件，也不自动发布到外网。
- 页面保持计划中的画幅，窄屏时整体缩放画布，不任意重排正文。核对字体与单位，避免把 CSS 像素直接当作 PPT 点数。
- 提供方便的翻页和页面定位方式。工具按钮、修改提示与预览页码放在画布外，不进入最终幻灯片。
- 用户可按页反馈文字与排版。若提供浏览器内文字编辑，必须能保存或导出修改，恢复已保存内容时不能覆盖文件中更新的修订。
- 实际用浏览器逐页检查文字、图像、连线与导航，并验证已提供的翻页、修改和保存功能。文件存在不能替代加载验证。

修改文字时同步到 MD；修改视觉时更新 HTML。以最新可读取的审阅件为准，保留已有修改，不能重建时退回旧文字。另存新版本，记录受影响页面，交付后等待当前预览确认。

## 可编辑 PPT 成品

按确认后的文字与预览制作 PPT。文本、表格、图表和需要修改的关系图保持原生可编辑；插画和背景可用图片，不以整页截图替代页面。

HTML 与 PowerPoint 的文字度量可能不同，优先调整文本框、间距和布局，不擅自删内容或缩成小字。必须明显改变已确认内容或构图时，先更新对应审阅件并确认受影响部分；技术性修正不反复确认。

渲染全套并对照预览，验证内容、页序、导航、字体、图片和可编辑性。备注及其他视觉要求按 [视觉规范](design-system.md)处理。制作与检查记录留在工作区。

## 确认、版本与文件交付

简要记录当前阶段、文件和已确认版本，格式不限，不混入上屏文字或技能资源。修改意见、沉默或经过一段时间都不等于确认。用户已提供明确确认的文字稿或预览时直接沿用，不从头开始。

文件链接指向实际交付文件。加载失败时检查文件、路径解析、资源与脚本；可提供短文件名、不带页面片段参数的直接入口，在文件内部指定起始页。只说明实际验证范围，不把单一浏览器的检查说成已验证所有客户端。

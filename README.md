# ppt-production 1.0 使用说明

将原始材料逐步整理成可编辑的演示文稿：先确认文字，再调整视觉，最后制作 PPT。

[查看仓库](https://github.com/Miku13520/ppt-production) · [下载 1.0 安装包](https://github.com/Miku13520/ppt-production/raw/refs/heads/main/dist/ppt-production-v1.0.zip)

## 适合做什么

适用于工作汇报、课程展示、方案说明、研究答辩，以及现有演示文稿的重做或局部调整。支持根据用户提供的 PPT、截图等参考学习视觉风格。

skill 保存通用制作方法，不附带固定主题、案例、人物、机构、原始文档或演示样稿。参考文件中的身份和具体内容不会自动带入新项目。

本说明面向 Codex。实际读取文件、生成 PPT、生图和渲染检查，需要当前使用环境具备相应工具；安装 skill 本身不会安装 PowerPoint 或其他制作软件。

## 一、下载安装

### 方法 A：下载压缩包后安装

1. 点击上方的“下载 1.0 安装包”。
2. 解压，找到名为 `ppt-production` 的文件夹。
3. 将整个文件夹放入个人技能目录。不要只复制 `SKILL.md`。
4. 在 Codex 的下一轮对话中尝试调用；如果没有出现，重启 Codex 后再试。

新环境可使用以下个人技能目录：

| 系统 | 个人技能目录 | 打开方式 |
| --- | --- | --- |
| Windows | `%USERPROFILE%\.agents\skills` | 将路径粘贴到资源管理器地址栏 |
| macOS / Linux | `~/.agents/skills` | 在文件管理器中打开用户主目录下的对应文件夹 |

目录不存在时可以新建。已有安装的环境应沿用实际识别到的技能目录，避免在多个位置重复安装同名技能；配置了其他安装位置时，以当前环境为准。

安装后应为以下结构，注意不要多套一层 `ppt-production`：

```text
skills/
└── ppt-production/
    ├── SKILL.md
    ├── agents/
    │   └── openai.yaml
    └── references/
        ├── content-and-review.md
        ├── design-system.md
        ├── page-patterns.md
        ├── review-workflow.md
        └── style-transfer.md
```

安装包已经包含所需的技能说明文件。项目素材和制作结果另外保存在项目文件夹中。

### 方法 B：让 Codex 协助安装

可以在支持技能安装的 Codex 环境中发送：

```text
使用 $skill-installer，从 https://github.com/Miku13520/ppt-production
安装 ppt-production 到个人技能目录。
技能位于仓库根目录；如果已有安装，先核对现有版本，不重复安装。
```

如果希望固定使用 1.0，而不是仓库未来更新后的内容，请明确要求使用 `dist/ppt-production-v1.0.zip` 安装包。

个人技能目录、通过安装器从其他仓库安装，以及技能未出现时重启的说明，参见 [官方 OpenAI 技能文档](https://learn.chatgpt.com/docs/build-skills)。

## 二、第一次使用

准备好材料，在 Codex 中附上文件，或提供当前环境能够访问的文件路径。若有风格参考，请说明哪些文件提供内容、哪些只用于参考画风。

可以直接发送：

```text
使用 $ppt-production，根据我提供的材料制作演示文稿。
用途：课程展示。
听众：具有基本背景知识的同学。
预计时长：10 分钟。
先生成 Markdown 上屏文字稿，等我确认后再生成完整 HTML 预览；
预览确认后，再制作可编辑 PPT。
```

用途、听众、时长可以按实际情况替换。不确定页数时可以不填，让助手按内容规划。需要保留的文字、数据、结论、标识或格式要求应提前说明。

## 三、完整制作流程

| 阶段 | 你会收到什么 | 你需要检查什么 | 如何进入下一阶段 |
| --- | --- | --- | --- |
| 文字审阅 | 实际 `.md` 文件 | 内容准确性、标题、要点、页序和必要限定 | 明确确认文字稿 |
| 视觉审阅 | 完整 `.html` 逐页预览 | 字号、图文关系、流程、导航和整体画风 | 明确确认预览 |
| 成品制作 | 可编辑 `.pptx` 文件 | 实际放映效果及需要编辑的对象 | 完成渲染检查后交付 |

### 第一步：确认上屏文字

Markdown 稿只保留实际需要出现在幻灯片上的标题和文字，包括目录条目、表格文字、流程节点，以及必要的来源和条件。不附讲稿、图示建议、排版说明或制作记录。

你可以直接修改 `.md` 文件并告知助手读取，也可以按页提出修改意见。直接改文件时，应提供修改后的实际文件，避免助手继续使用旧稿。

确认时可以发送：

```text
文字稿已确认，请以当前修订稿为准，生成完整 HTML 预览。
```

### 第二步：调整 HTML 预览

打开交付的 HTML，逐页查看。优先使用浏览器打开；如果另有资源文件夹，应与 HTML 一起保留。预览显示整套演示的视觉效果，不只是封面和几张样页。

反馈时尽量给出页码、对象和具体问题，例如：

```text
第 5 页：完整流程放在同一页，箭头不要穿过文字。
第 8 页：标题和导航放在同一行，导航文字两侧增加留白。
第 12 页：内容正确，但页面过于单薄，请增加相关的场景示意。
本次只调整视觉，不改动已确认文字。
```

如果预览提供文字修改功能，修改后使用实际提供的保存或导出功能，并把保存后的文件交给助手。不要只关闭浏览器，假定所有修改都已经保存。

确认时可以发送：

```text
当前 HTML 预览已确认，请按这个版本生成可编辑 PPT。
备注栏保持为空，并检查全套页面的文字、图像、导航和可编辑性。
```

“第几页需要调整”等修改意见不会被当作进入下一阶段的确认。若要跳过某个阶段，请明确说明。

### 第三步：使用 PPT 成品

成品应与确认的文字和预览一致。标题、正文、表格、图表和需要修改的关系图保持可编辑；插画和背景可以是图片。

打开 PPT 后，可以在演示软件中继续修改文字、替换素材和放映。HTML 与演示软件的字体度量可能不同，因此成品还需要独立渲染检查；如果使用环境缺少制作或渲染工具，助手应说明实际限制。

## 四、1.0 版的默认效果

- 默认采用 16:9 画幅，大字号、清楚分区，标题和重点加粗，正文保留正常字重。
- 页面标题只写主题，不用“标题：解释内容”的拼接方式。
- 正文页标题在页眉左侧，章节导航在右侧，二者位于同一栏；正文排在其下。
- 导航根据实际章节设置，文字两侧留白充分，常态和高亮文字保持垂直居中。
- 完整流程和能够同页展示的同类要点不机械拆成两页；复杂内容按独立子主题展开。
- 多章节完整演示默认包含封面后的目录和结尾感谢页；封面、目录、感谢页通常不放进度栏。
- 不添加无关的小字、页脚角标或重复总结；必要的来源、单位和限定保留。
- 备注栏默认留空。
- 需要视觉主体时使用相关图片或图解；素材不足时可按环境能力使用生图工具。
- 概念插画不充当真实场地、实测数据或业绩证据，不虚构事实来填充页面。

这些是可调整的默认值。当前项目明确提出的品牌、模板和视觉要求优先。

## 五、常用请求

### 参考现有模板

```text
使用 $ppt-production。
正文内容以我提供的材料为准，另附的 PPT 只作为视觉参考。
学习其字体层级、配色、图形和图文关系；不要带入其中的人名、机构、标识或案例内容。
先给我 Markdown 上屏文字稿。
```

### 只修改现有演示

```text
使用 $ppt-production，调整我提供的现有演示。
只修改第 3–5 页的字号、导航和图文排版，保留内容与其余页面。
请另存为新版本。
```

现有演示的局部修改按本次要求处理，不默认重新进行整套内容规划。

### 从已有审阅稿继续

```text
使用 $ppt-production。附件是最新 HTML 预览和文字稿。
文字已经确认，当前仍在视觉调整阶段。
请基于附件继续，不退回旧稿，也不要提前生成 PPT。
```

### 允许补充概念插画

```text
需要图片解释场景时，可以调用生图工具。
插画与当前配色保持一致，不加入企业标识或未经提供的事实。
标题、正文和功能性流程图继续保持可编辑。
```

## 六、常见问题

**只下载 `SKILL.md` 可以吗？**

不够。它引用了 `references` 中的规则，安装时应保留完整的技能文件夹。

**必须连接 GitHub 插件才能下载吗？**

这个仓库是公开仓库，可以直接在浏览器下载安装包。能否自动下载安装取决于当前环境的网络与工具；不必为手动下载先完成 GitHub 写入授权。

**安装后找不到技能怎么办？**

检查文件夹层级、`SKILL.md` 文件名及安装位置。确认没有多套一层文件夹，也没有把整个仓库压缩包误当作技能文件夹。下一轮对话仍未识别时重启 Codex，并避免重复安装同名版本。

**为什么先得到文字稿，没有直接生成 PPT？**

这是默认审阅流程。确认文字稿后生成 HTML，确认预览后生成 PPT。可以明确要求跳过阶段，但通常先校对内容能减少后续返工。

**HTML 无法加载怎么办？**

告诉助手交付文件无法打开，提供文件名和实际报错。可要求检查资源是否齐全，并提供短文件名、可直接打开的离线入口。不要仅凭文件存在就认定加载正常。

**安装后会自动得到完整 PPT 制作环境吗？**

不会。skill 提供工作方法与质量要求，实际制作依赖当前环境的文件处理、演示文稿工具、字体和渲染能力。缺少生图工具不代表不能使用技能，可以使用现有素材或可编辑图解。

**会把我的材料保存进技能或上传到 GitHub 吗？**

技能要求将项目文稿、素材、预览和检查记录保存在项目工作区，通用技能包与项目内容分开。制作演示不等于授权对外上传或发布。

**如何更新版本？**

保留需要的旧版备份，再将目标版本完整安装到已有技能位置，避免仅替换主文件造成引用文件版本不一致。项目材料和生成结果保存在独立文件夹中。

## 七、文件说明

| 文件或目录 | 用途 |
| --- | --- |
| `SKILL.md` | 技能入口、适用范围和审阅流程 |
| `agents/openai.yaml` | 显示名称、默认调用提示和调用设置 |
| `references/` | 视觉、页面表达、风格迁移、审阅及检查规则 |
| `dist/ppt-production-v1.0.zip` | 仓库中提供的 1.0 安装包 |

本说明是面向使用者的文档，不属于 1.0 安装包中的七个技能文件。它不会改变已发布的技能规则和版本。
